# 04. Diff — 텍스트 변경 (TEXT patch)

- 요구사항: R-P1-02 (두 Virtual DOM을 비교해 변경된 부분을 찾는 Diff 알고리즘)
- 코드: `src/diff.js`의 `walk` 안 텍스트 노드 비교 부분
- 테스트: `tests/diff.test.js`의 "텍스트 변경(TEXT)"
- 범위: 텍스트가 다르면 에러 대신 `TEXT` patch를 돌려주기. 실제 DOM 반영(Patch, R-P1-03)은 하지 않는다.
- 이전 노트: [03-diff-no-change.md](03-diff-no-change.md)

## 한 줄 요약
같은 위치의 텍스트 노드끼리 글자가 다르면 `{ type: 'TEXT', path, text: 새 글자 }`를 patch 배열에 넣는다.

```js
if (oldNode.text !== newNode.text) {
  patches.push({ type: 'TEXT', path, text: newNode.text });
}
```

## 예시

| 상황 | old → new | 결과 |
|---|---|---|
| 루트가 텍스트 | `'hello'` → `'bye'` | `[{ type: 'TEXT', path: [], text: 'bye' }]` |
| 루트 요소의 자식 | `<p>hello</p>` → `<p>bye</p>` | `[{ type: 'TEXT', path: [0], text: 'bye' }]` |
| 중첩 | `<div><h1>t</h1><p>hi <b>there</b></p></div>`에서 `there` → `you` | `path: [1, 1, 0]` |
| 빈 문자열 | `'hello'` → `''` | `[{ type: 'TEXT', path: [0], text: '' }]` |
| 여러 곳 | `<ul>`의 `one`, `three`를 대문자로 | `[0, 0]` 다음 `[2, 0, 0]` |

중첩 예시의 path 읽는 법: div의 `children[1]`(p) → p의 `children[1]`(b) → b의 `children[0]`(텍스트).

## 여러 텍스트가 바뀔 때의 순서
`walk`는 위에서 아래로, 왼쪽에서 오른쪽으로(깊이 우선) 내려가며 비교한다. 그래서 patch도 트리에 나오는 순서대로 쌓인다. 비교를 멈추지 않고 끝까지 돌기 때문에 바뀐 곳이 여러 개여도 모두 담긴다.

## 이번 작업에서 정한 것
- **patch에는 새 글자만 담는다:** 텍스트 노드를 바꿀 때는 새 글자만 있으면 된다. 이전 글자는 담지 않는다.
- **빈 문자열로 바뀌는 것도 TEXT다:** 노드를 지우는 게 아니라 글자를 비우는 것으로 본다. 텍스트 노드가 아예 사라지는 경우(자식 개수 변경)와는 다르다.
  - 그래서 이 테스트는 VDOM을 직접 만들었다. `innerHTML = '<p></p>'`는 텍스트 노드 자체를 만들지 않기 때문이다.
- **공백만 바뀌어도 변경이다:** 01에서 정한 "공백 보존" 규칙과 같다. `'a b'` → `'a  b'`도 TEXT patch가 나온다.
- **patch마다 path는 서로 다른 배열이다:** 자식으로 내려갈 때 `[...path, i]`로 새 배열을 만들기 때문이다. 한 patch의 path를 고쳐도 다른 patch에 영향이 없다.

## 질문 기록
**Q. `path: [1, 1, 0]`에서 h1이 1, b가 1, there가 0인가?**

A. b가 1, there가 0인 것은 맞다. 하지만 경로의 첫 번째 `1`은 h1이 아니라 **p**다. 숫자 하나는 "그 단계에서 몇 번째 자식으로 내려갔는지"이고, h1은 이 경로에 들어 있지 않다.

테스트 입력은 공백 없이 붙여 쓴 HTML이다.

```
<div><h1>t</h1><p>hi <b>there</b></p></div>

[]         <div>
[0]        <h1>        ← h1은 0번째
[0,0]      "t"
[1]        <p>         ← 첫 번째 1
[1,0]      "hi "
[1,1]      <b>         ← 두 번째 1
[1,1,0]    "there"     ← 마지막 0
```

같은 내용을 **들여쓰기해서** 쓰면 줄바꿈·들여쓰기도 텍스트 노드로 보존되므로(01 노트 규칙) 인덱스가 밀린다.

```
<div>
    <h1>t</h1>
    <p>hi
       <b>there</b>
             </p>
</div>

[]         <div>
[0]        "    \n    "   ← 공백 텍스트
[1]        <h1>           ← 이 경우엔 h1이 1번째
[1,0]      "t"
[2]        "\n    "
[3]        <p>
[3,0]      "hi \n       "
[3,1]      <b>
[3,1,0]    "there"        ← 경로는 [3, 1, 0]
[3,2]      "\n             "
[4]        "\n"
```

(실제로 `domToVdom`을 실행해 출력한 결과다.) 그래서 path를 셀 때는 공백 텍스트 노드도 자식으로 세야 한다.
